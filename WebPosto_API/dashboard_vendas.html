O que minha CHAVE está liberada a fazer?

A Quality/WebPosto não envia uma lista formal de módulos no JSON. O contrato real aparece na prática: HTTP 200 = a chave pode chamar aquele GET (com ou sem dados); 403 = chave reconhecida, mas sem permissão naquele endpoint ou filial; 401 = chave inválida ou expirada. Usa as datas e filial dos parâmetros globais (mesmo contexto dos relatórios). Para varredura completa no terminal, rode python diagnostico_api.py na pasta do projeto.

💰 Relatório de despesas e caixa (via API)

Característica: financeiro · 3 fontes diferentes
Sobre despesas e o que o frentista lança no caixa: na API REST não existe um endpoint chamado “sangria” com lista linha a linha como no PDV. O que costuma existir na integração é o seguinte:

(1) TITULO_PAGAR — títulos / contas a pagar (fornecedor, histórico, valor, situação). Se o WebPosto gravar usuário, plano de contas ou datas nesses registros, a tabela abaixo tenta exibir todos os campos que a API devolver (nomes variam por versão/contrato).

(2) CAIXA — um registro por turno (abertura, fechamento, apurado, diferença). Não é extrato de cada retirada.

(3) CAIXA_APRESENTADO — conferência por forma de pagamento (apresentado × apurado).

(4) FINANCEIRO_EXCLUSAO — quando no WebPosto está habilitado algo como gerar débito em financeiro na conta caixa (conforme documentação do cliente), este GET pode trazer lançamentos mais próximos de “saída de caixa” / exclusões. Depende de configuração e permissão da chave.

(5) Títulos a receber + cartão (remessa / pagar / compra) — abaixo: contas a receber (inclui títulos ligados a cartão), remessas de cartão e demais consultas oficiais da integração para conciliar recebíveis de maquineta. Para cada sangria pontual feita no PDV, a Quality pode expor outros relatórios só no sistema desktop ou em rotas extras — vale conferir o Swagger com a sua CHAVE.

📋 Despesas / contas a pagar

GET /INTEGRACAO/TITULO_PAGAR

Característica: visão de “despesa” em reais — data do movimento (baixa/pagamento/liquidação) e data de lançamento (inclusão/cadastro/emissão) em colunas separadas; vencimento, competência, funcionário, pago/saldo, plano, filial.

Atenção: não é extrato de caixa; campos dependem do cadastro e do retorno real da API.

Limitação: não lista automaticamente cada despesa ou sangria linha a linha — é consolidação do turno.

⚖️ Conferência no caixa

GET /INTEGRACAO/CAIXA_APRESENTADO

Característica: dinheiro, cartão, cheque, etc. — valores apresentados × apurados e diferenças.

Uso: auditar conferência física do caixa, não o plano de contas de despesas.

📤 Débito caixa / exclusões (possível sangria)

GET /INTEGRACAO/FINANCEIRO_EXCLUSAO

Pesquisa: endpoint usado quando há débito de caixa no financeiro. Pode aproximar retiradas/sangrias refletidas como movimento financeiro — não substitui o extrato interno do PDV.

Se retornar vazio ou 403: filial/configuração ou permissão da chave.

Visão geral da integração WebPosto (Quality Automação)

A API expõe rotas sob o prefixo /INTEGRACAO/.... Quase todas as chamadas exigem o parâmetro de consulta CHAVE (sua chave de integração). Nesta tela, o servidor local (proxy) injeta a CHAVE a partir do campo que você preencheu ou do arquivo .env, para você não precisar colá-la em toda requisição manual.

Catálogo = tudo que esta ferramenta sabe chamar: cada linha do inventário (aba Diagnóstico) e cada opção do select (aba Explorador) é uma rota que você pode disparar daqui, com o método HTTP indicado (GET, POST ou PUT). Ou seja: tudo que está no catálogo está coberto pelo proxy e pela interface.
Quando dá certo de verdade: a API WebPosto precisa aceitar a chamada. Isso depende da sua CHAVE ter permissão para aquela operação e filial, dos parâmetros e do body JSON estarem corretos (POST/PUT), e dos IDs na URL existirem (PUT). Sem isso você pode ver 401, 403, 400 ou 404 — a rota continua “fazível” na ferramenta, mas o servidor recusa ou corrige o pedido.

Documentação interativa (contrato oficial): Swagger UI · JSON OpenAPI: /v3/api-docs

GET — consultar e listar (não altera o servidor)

O que é: você pede um recurso ou uma lista; o servidor devolve dados. É a operação mais segura para testes e relatórios.

Quando usar no WebPosto: vendas, abastecimentos, clientes, produtos, títulos a pagar/receber, caixa, estoque, notas fiscais, etc. — tudo que o catálogo marca como GET.

Parâmetros típicos (query string):

  • dataInicial / dataFinal — filtro por período (quando a rota suporta).
  • pagina / tamanhoPagina — paginação por “página” em várias listas.
  • ultimoCodigo — em algumas listas (ex.: abastecimento) a documentação usa cursor em vez de só página; avance com o último código retornado.
  • filial — uma ou mais filiais (às vezes lista ou CSV, conforme a rota).
  • Outros filtros específicos: codigo, cpfCnpj, bico, etc.

Boas práticas: comece com intervalo de datas curto e tamanhoPagina moderado para não sobrecarregar rede nem o servidor.

POST — criar ou disparar uma ação nova

O que é: você envia um corpo JSON com os campos exigidos pela rota. O servidor normalmente cria um registro ou processa um comando que não é só “ler”.

Quando usar no WebPosto: cadastrar cliente, lançar título, registrar movimento, integrar prazos, vincular entidades, etc. — tudo que o catálogo marca como POST.

Efeito: pode gerar dados novos no banco do posto. Não é idempotente por padrão: enviar duas vezes o mesmo POST pode criar dois registros, salvo quando a API deduplica internamente.

O que preencher nesta tela: além da query (se houver), edite o campo Body JSON com o payload exato. O formato correto está no OpenAPI/Swagger da rota correspondente.

PUT — atualizar recurso existente

O que é: você indica qual registro alterar (muitas vezes pelo id ou outros códigos na URL, por exemplo /INTEGRACAO/CLIENTE/123) e envia no corpo os campos a atualizar (conforme contrato da rota — às vezes o objeto completo).

Quando usar no WebPosto: corrigir cadastro, atualizar título, ajustar veículo de frota, reajustar estoque de combustível, etc. — rotas marcadas como PUT no catálogo.

Atenção: PUT pode sobrescrever dados. Confira ambiente (homologação x produção) e confirme o ID na URL antes de enviar.

PATCH e DELETE — uso pontual

PATCH: em APIs REST costuma significar “atualização parcial”. O proxy deste explorador aceita PATCH se você estender a ferramenta ou chamar a API diretamente; o catálogo local foca nas rotas GET/POST/PUT mapeadas no projeto.

DELETE: remoção de recurso. Só use se a documentação oficial da Quality expuser a rota e sua chave tiver permissão.

Para qualquer método fora do catálogo, use o Swagger ou monte a requisição manualmente com a mesma base URL e CHAVE.

Códigos HTTP que você vai ver com frequência

CódigoSignificado prático
200Sucesso genérico; corpo costuma trazer JSON com lista ou objeto.
201Criado — comum após alguns POST bem-sucedidos.
400Requisição inválida: parâmetro faltando, JSON mal formado, regra de negócio rejeitou o payload.
401Não autenticado: CHAVE ausente, inválida ou expirada.
403Autenticado mas sem permissão para aquela operação ou filial.
404Rota ou recurso não encontrado (path errado ou ID inexistente).
409 / 422Conflito ou validação — depende da API; leia a mensagem no corpo.
500 / 502 / 503Erro no servidor ou indisponibilidade; tente depois ou abra chamado na Quality.

Como esta tela avançada encaixa isso tudo

  • Aba Explorador: escolhe qualquer rota do catálogo, monta query e body, e envia via POST /api/explorer/proxy para o seu computador repassar à API WebPosto (evita CORS no navegador).
  • Aba Diagnóstico: lista 100% das rotas catalogadas com método, caminho e notas — é o inventário completo do que esta tela pode executar.
  • Esta aba Guia: explica o significado de cada verbo HTTP e o que esperar na prática — use junto do Swagger para os detalhes de cada campo.

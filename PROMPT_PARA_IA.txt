# BRIEFING COMPLETO — PROJETO API WEBPOSTO + SISTEMA INTERNO

## 🎯 OBJETIVO
Reconstruir um sistema integrado que sincroniza dados da API WebPosto (51 endpoints de combustível, vendas, financeiro, frota) com um sistema interno de auditoria e processamento em tempo real.

## 📊 ARQUITETURA GERAL

### Stack Tecnológico:
- **Backend**: FastAPI 0.124.4 (Python 3.14.0)
- **Banco de Dados**: MongoDB 5.0 + Redis 7.0
- **Proxy/Load Balancer**: Nginx
- **Monitoramento**: Prometheus + Grafana
- **Containerização**: Docker Compose
- **Validação**: Pydantic v2.12.5
- **Testing**: pytest 9.0.1 + pytest-asyncio

### Arquitetura de Código (DDD):
```
/domain         → Entidades e lógica de negócio
/application    → Casos de uso e orquestração
/infrastructure → Banco de dados, APIs externas
/interfaces     → Rotas HTTP (FastAPI)
```

## 🔐 CREDENCIAIS E CONFIGURAÇÃO

### Token WebPosto:
- **Variável**: WEBPOSTO_BEARER_TOKEN (veja arquivo .env)
- **Capacidades**: Acesso COMPLETO a 51 endpoints
- **Operações**: GET (consulta), POST (criar), PUT (atualizar), DELETE (soft delete)
- **Auditoria**: Todas operações rastreadas com X-Usuario e X-Motivo headers

### Endpoints WebPosto (51 total):
- Abastecimento (combustível, divergências, encerrantes)
- Clientes (dados cadastrais, frota, grupos)
- Produtos (combustível, estoque, preços)
- Financeiro (títulos receber/pagar, caixa, cartão)
- Vendas (notas fiscais, pedidos, múltiplas filiais)
- Relatórios (vendas, estoque, performance)
- Administração (usuários, filiais, grupos)

## 🔄 FLUXO PRINCIPAL DE INTEGRAÇÃO

1. **Sincronização Inicial**
   - Baixar todos os dados da API WebPosto
   - Validar com Pydantic
   - Armazenar em MongoDB
   - Indexar em Redis para performance

2. **Processamento em Tempo Real**
   - Webhook ou polling (a cada 1 hora)
   - Detectar mudanças vs. última sincronização
   - Atualizar registros modificados
   - Registrar em auditoria com hash

3. **Auditoria Completa**
   - QUEM fez? (X-Usuario header)
   - O QUÊ fez? (operação: GET/POST/PUT/DELETE)
   - QUANDO fez? (timestamp automático)
   - ONDE fez? (IP capturado)
   - POR QUÊ fez? (X-Motivo header)
   - VALORES ANTES? (backup automático)
   - VALORES DEPOIS? (novo estado)
   - HASH? (verificação de integridade)

## ⚠️ CONSIDERAÇÕES IMPORTANTES

1. **Segurança**:
   - Token NUNCA deve estar em logs ou documentação pública
   - Usar variáveis de ambiente (.env)
   - HTTPS obrigatório em produção
   - Rotação periódica de token recomendada

2. **Performance**:
   - Usar índices no MongoDB para queries frequentes
   - Cache em Redis para dados pouco mutáveis
   - Paginação obrigatória para grandes volumes
   - Conexão pooling habilitada

3. **Rate Limiting**:
   - API WebPosto: 1000 req/hora, 100 req/minuto, 10 simultâneas
   - Implementar retry com backoff exponencial
   - Se erro 429: aguardar 60 segundos

4. **Erro Handling**:
   - 400: Validação falhou (ver detail)
   - 401: Token expirado
   - 403: Sem permissão
   - 404: Recurso não encontrado
   - 422: Erro de validação Pydantic
   - 429: Rate limit excedido
   - 500: Erro interno (logar e alertar)
